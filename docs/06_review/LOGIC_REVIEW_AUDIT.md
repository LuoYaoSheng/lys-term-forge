## 七、两个 A 类勘误独立复核专项结论

### 勘误① PL-02：TOFU 指纹口径 —— **核心论断成立；波及清单一处失实（已修）**

**独立复核（读 client.rs 源码）**：
- L22 注释原文确为 `/// Compute a hex SHA-256 fingerprint of the remote host key.`；
- L23-33 实现：`sess.host_key()` 取 raw key 字节 → L27-31 逐字节 `{:02x}` 以冒号连接 → L32 返回。**函数体内无任何 SHA-256/Digest 调用**（sha2 的引用在 crypto.rs，client.rs 未引入）。
- 结论：**注释与实现不符、实现为 raw key hex dump 的论断完全成立**；「重开发照文档实现 SHA-256 将与既有 known_hosts 数据不兼容（raw hex vs SHA-256 摘要必然不匹配，全部触发 MITM 告警）」的后果推理成立。
- **波及清单复核**：P1 REVERSE_ANALYSIS 两处失实表述（§⑤ F024 行 L304「SHA-256 指纹」、§② 持久化实体 L443「sha256hex指纹」）✔；P2 PRD L68 数据文件树 ✔（但其 F024 功能行 L104 与验收详情 L301 均未写算法，原勘误把位置标为「PRD F024」不准）；P4 B-12 规格 L157「显示…SHA-256 指纹」✔；**P3 PAGE_SPEC 全文既无「SHA-256」也无「指纹」字样（§2.4 仅写 "known_hosts 0600"），原勘误将其列入波及清单属失实**——已按 A1/A2 修正（波及实为 P1/P2/P4 三份，PAGE_SPEC 无需勘误）。
- **六件套留痕检查**：勘误在 PL 总册 §5.1（专节+问题表 PL-02 行+§六 Top5 第 5 条）、UF-04（新证据）、§5.4 表（B-12 实施前置条件）三处留痕，且 08_development/PERMISSION.md、ERROR_CODE.md、03_flow 等下游产物已采纳——**留痕清晰、传导充分**。

### 勘误② PL-03：auth 死代码 "Try default agent first" 恒 false —— **完全成立，零瑕疵**

**独立复核（读 client.rs 源码）**：
