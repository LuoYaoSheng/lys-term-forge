## 一、核心流程路径对比（最快路径 vs 现路径）

### F1 日常登录排查（P1 画像 S1：打开应用→双击已存连接→敲命令→关 Tab）

| 环节 | 理想最快路径 | 现路径（代码实测） | 评价 |
|---|---|---|---|
| 触发 | 启动应用 | 同 | — |
| 找到连接 | 双击列表项 | 双击 `.saved-item`（ConnectionForm L122-130）= 回填+立即 dispatch connect | 达标（但入口可发现性弱，P4 F-06/B-07） |
| 建立 Tab | 自动 | createTab（App.svelte L160-175） | 达标 |
| 连接 | 自动 | connecting → session_open（TerminalTab L115-158） | 达标 |
| 使用 | 键入即达 | session_send → IO 线程 → app_event → xterm | 达标 |
| 结束 | Ctrl+W | closeTab → session_close（App.svelte L177-194） | 基本达标（close 失败 Toast 后 Tab 仍移除，P4 FL-04） |

**结论：主链路健康，2 步可用，这是产品当前最有价值的部分。**

### F2 首次连接新机器并保存（S2）
填写表单（4 字段）→ Connect → 首连 TOFU 自动记录（client.rs L65-74，无确认）→ 使用 → 回表单再填一遍同样内容 → Save。
**断点：连接成功后想保存，必须重新填写一遍刚输入的参数**（Connect 不落盘、Save 无「保存当前连接」捷径、也无「连接成功后询问是否保存」）。现路径 8+ 步，理想 5 步。

### F3 凭据轮换（改密码后重连）——运维高频
现路径（实测）：连接报 "Authentication failed — check username and password" → 回侧栏改密码表单 → **Reconnect 无效**（用 Tab 创建时的 connection 快照，App.svelte L17-28；改表单不影响已建 Tab）→ 无编辑连接入口（表单无编辑按钮）→ 即使有，Save 也必生成新 UUID（ConnectionForm L77 `conn_${crypto.randomUUID()}`）走新增而非按 id 更新（store.rs L114-115 的更新能力前端不可达）→ 查重拦截（L67-74）→ **唯一出路：关 Tab → 重填 → 重连**。
**三重锁死：快照重连 + 无编辑入口 + UUID 新增。理想路径 3 步（改密码→保存→重连），现路径 6 步且语义上像在惩罚用户。**

### F4 连接失败处置（S3）
六种 friendlyError 映射（TerminalTab L105-113）+ Reconnect 按钮（error 态）→ 结构达标。
缺口：(a) 密钥场景提示错位（UF-05）；(b) Ctrl+R 死文案（P4 FL-01）；(c) 主机密钥变更被兜底文案吞（P4 FL-10/B-13）。

### F5 会话中断处置（S4）
- 远端正常断开：终端一行 `[status] closed: ...`（L131）→ **无重连按钮**（P4 FL-02/B-05）。
- 网络读错误：一行 `[status] error: Read error: ...` → **状态仍 connected、无按钮、输入静默丢弃**（ST-01，本评审新发现，P4 未覆盖）。
- 非激活 Tab 断线：无全局信号（P4 FL-11）。

### F6 保存/删除连接（含查重）
Save：校验→查重→加密→Toast→刷新，链路完整；删除：confirm→delete→Toast→刷新，完整（confirm 为原生对话框，P4 F-05/B-06）。

### F7 慢连接（15-30s 完成）
前端 15s 置 error 报 "Connection timed out"（TerminalTab L143-150）；后端无取消协议，若 18s 连上：会话注册、事件被过滤、UI 与事实分裂（ST-03）。用户重连 → 双会话。

### F8 首次连接的信任决策（TOFU）
首连自动写 known_hosts（client.rs L65-74），用户全程无感知；指纹展示口径与文档不符（UF-04）。

## 四、问题清单

> 格式：当前设计 / 问题 / 影响 / 建议方向。分级沿用 A/B/C/D。与 P4 重叠的条目交叉引用，只补增量证据。

### UF-01【B】凭据轮换流程三重锁死（P4 F-02/FL-03 汇总升级 + 新证据）
- **当前设计**：① Reconnect 使用 Tab 创建时的 connection 快照（App.svelte L17-28，TerminalTab L148 `sessionOpen({...connection})`）；② 无编辑连接入口；③ Save 每次生成新 UUID（ConnectionForm L77），后端按 id 更新（store.rs L114-115）永不可达，且查重拦截同名/同三元组保存（L67-74）。
- **问题**：三条路径全部堵死「改密码→继续用」这一运维高频诉求；P4 分别记录了前两条，未指出 UUID 使更新能力双重不可达。
- **影响**：密码轮换后用户被迫关 Tab 重填；配合 DS-01（密码静默失效）后，用户体验为「保存的密码随机失灵且无法修复」。
- **建议方向**：重开发流程规格中定义「编辑连接」闭环：列表项编辑入口 → 表单按 id 更新 → 已开 Tab 提供「使用新凭据重连」；或最低限度在认证失败文案中告知「请关闭此 Tab 并重新连接」（P4 B-08 已做呈现层）。

### UF-02【B】运行时读错误后用户路径中断：无提示、无下一步、无恢复（P4 未覆盖）
- **当前设计**：读错误仅终端打印 `[status] error: Read error: ...`（TerminalTab L131），状态不变（L132 仅处理 closed，见 ST-01），无按钮；后续输入 `.catch(() => {})` 静默（L84）。
- **问题**：五要素中「异常与恢复」整体缺失；用户面对一个看起来健康（绿点）但已死的终端。
- **影响**：最恶劣的用户体验场景——不是报错吓到用户，而是无声无息的失效。
- **建议方向**：与 ST-01 一并修复（状态映射 + Reconnect 条 + 输入失败至少一次 Toast）。

### UF-03【B】慢连接超时的误导路径与双会话（P4 未覆盖）
- **当前设计**：见 F7 与 ST-03——15s 前端超时无后端取消；后端 TCP read timeout 30s（client.rs L125）。
- **问题**：超时提示「Connection timed out」与后端可能已成功的事实矛盾；重连产生孤儿会话。
- **影响**：慢链路用户被引导去查网络（实际已连上）；远端遗留 sshd 会话与本机句柄泄漏。
- **建议方向**：超时后前端对 pending 连接发 session_close（幂等）；或后端支持取消；提示文案改为「连接仍在尝试中，已超时——可重试或等待」需与取消能力配套，先做取消。

### UF-04【B】TOFU 无确认 + 指纹口径与实现不符（P4 FL-09/B-12 交叉引用 + 新证据）
- **当前设计**：首连自动信任（client.rs L65-74）。**新证据**：`host_key_fingerprint` 注释与 P1/P2/P4 三份文档均称「SHA-256 指纹」（P3 PAGE_SPEC 未涉指纹算法口径），实现是对 raw host key 的逐字节 hex dump，无任何哈希（client.rs L22-33；波及清单经 2026-09-03 审计复核修正）。
- **问题**：确认式 TOFU 若按文档口径实现（展示 SHA-256 指纹）将与既有 known_hosts 数据不兼容（存储的是 raw hex）；文档勘误见 PL-02。
- **影响**：重开发照文档实现会静默不匹配旧数据，全部已存指纹触发 MITM 告警。
- **建议方向**：先勘误口径（A 类），再实现确认式 TOFU（P4 B-12 规格）；指纹格式变更需带迁移。

### UF-05【D】密钥认证失败的提示错位（P4 未覆盖，轻微）
- **当前设计**：无密码无 key_path 时探测 ~/.ssh 三把密钥（client.rs L152-179），失败报错 "Authentication failed: no password provided and no suitable SSH key found"（L181-185）；前端 friendlyError 按 "Authentication" 命中 → "check username and password"（TerminalTab L108）。
- **问题**：密钥用户的失败被导向「检查用户名密码」，与实际（密钥不被接受/不存在）错位。
- **影响**：低频但方向性误导。
- **建议方向**：观察；若做 F045 密钥 UI（C 类）则一并区分两类认证错误文案。

### UF-06【D】错误提示 Ctrl+R 死文案（P4 FL-01/B-04 交叉引用）
- TerminalTab L166；不重复展开。

### UF-07【D】connecting 态不可取消（P4 FL-06/D-5 交叉引用）
- 15s 兜底；与 UF-03 相关但独立（取消 vs 超时清理），随取消能力一并决策。

### UF-08【D】连接成功后保存需全量重填（P2 §3 场景 S2 的流程缺口）
- **当前设计**：Connect 与 Save 是两个独立动作，Connect 成功后表单内容仍在但 Save 需再次点击且 name 自动生成（ConnectionForm L65）——实际点击成本低；真正缺口是「连接中/成功后」没有任何保存引导。
- **影响**：新用户首连后直接开始工作，忘记保存，下次重填。
- **建议方向**：观察；可在连接成功 Toast 中附「保存此连接」动作（属新交互，随 C-1）。

### UF-09【D】占位视图引导缺「下一步动作」（P4 P-01/B-02 交叉引用）
- SFTP/Tunnel/Runbook 空态无按钮（SidePanel L148-156）；流程「下一步」要素缺失，原型层已处理，重开发规格需固化。

## 五、小结

| 分级 | 数量 | 编号 |
|---|---|---|
| B | 4 | UF-01、UF-02、UF-03、UF-04 |
| D | 5 | UF-05、UF-06、UF-07、UF-08、UF-09 |

流程层最关键结论：**正常路径（F1）已达产品化水准；但三类异常恢复路径（凭据轮换 UF-01、运行时错误 UF-02、慢连接 UF-03）系统性缺失或死路——恰好都是 P4 未覆盖或仅部分覆盖的增量发现。重开发的流程规格应把「异常恢复」从 P4 的 7 条 B 类扩展到包含本册 4 条 B 类的完整清单**。
