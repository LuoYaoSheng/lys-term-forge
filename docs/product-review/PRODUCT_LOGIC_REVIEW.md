## 四、功能取舍四档（对 P4 C-1「13 项」的独立建议）

> 四档口径：**一档=重构基线必做**（不做则既有核心价值有缺口）；**二档=建议纳入 MVP**（高价值、成本可控）；**三档=需用户决策**（大块范围、定义 MVP 边界）；**四档=暂缓**（低频/高成本/依赖前三档）。
> 注：P4 C-1 文字称「13 项」，其清单实列 14 个功能组（SFTP、隧道、Runbook、设置持久化、编辑连接、连接组织、自动重连、Keychain、危险命令确认、监控、复制粘贴、密钥认证 UI、更新通知、命令面板）——数量口径请一并确认（勘误级）。

| 档位 | 功能（PRD ID） | 理由 | 与 P4 C-1 建议的差异 |
|---|---|---|---|
| 一档·必做 | 复制粘贴（F044）、编辑连接（F035）、设置持久化（F034） | F044 是终端基本功能缺位；F035 是 UF-01 死路的唯一闭环（后端按 id 更新已在，纯 UI）；F034 是 IA-02 设置页重构的数据前提 | 与 P4 顺序一致（F044→F045→F035→F034）；本评审将 F034 提至一档（P4 列第 4） |
| 二档·应做 | 密钥认证 UI（F045）、命令面板真实命令集（F033） | F045：密钥是 P1 用户主流认证方式且后端已在，同时解决 PM-02 隐式使用；F033：壳已在、session_list（P4 D-1）是天然数据源，且快捷键输入态失效（IA-08）使全局入口更有价值 | F033 P4 排第 5，本评审明确二档 |
| 三档·用户决策 | SFTP（F029/F038）、隧道（F030/F039）、Runbook（F031/F040） | 三大块是「工作台 vs SSH 客户端」定位分水岭；工作量占规划总量大头；做多少、先做哪块必须用户拍板（同时决定 IA-01 占位视图策略） | 与 P4 C-1 一致（SFTP 列第 6、其余靠后） |

## 五、与 P4 评审的交叉对照（冲突 / 升级 / 勘误）

### 5.1 PL-02【A】指纹口径勘误（新增 A 类）

- 事实：client.rs L22-33 `host_key_fingerprint` 函数注释为 "Compute a hex SHA-256 fingerprint"，实现是对 raw host key 字节逐字节 hex（无任何哈希）。
- 波及文档（均写「SHA-256 指纹」）：docs/01_reverse/REVERSE_ANALYSIS.md（§② 持久化实体「sha256hex指纹」与 §⑤ F024 行）、docs/02_product/PRD.md（§1 数据文件树 known_hosts 行，F024 功能行与验收详情本身未写算法）、docs/06_review/PRODUCT_REVIEW.md（B-12 规格「显示…SHA-256 指纹」）。（勘误范围经元审计复核修正：PAGE_SPEC.md 全文未涉指纹算法口径（§2.4 仅写 "known_hosts 0600"），无需勘误——2026-09-03 审计 A1）
- 后果：重开发若照文档实现 SHA-256 指纹，将与既有 known_hosts 数据不兼容（全部触发 MITM 告警）。功能上 raw key 比较无安全损失，属文档口径错误。
- 建议：勘误四份文档表述为「主机公钥原始字节的十六进制串（非哈希指纹）」，或在重构时明确切换为 SHA-256 并带数据迁移（与 UF-04 联动）。

### 5.2 PL-03【A】认证分支死代码与注释误导（新增 A 类）

- 事实：client.rs L143-149「Try default agent first」分支在未尝试任何认证时检查 `sess.authenticated()`，恒为 false；且代码从未调用 ssh-agent 认证——该分支为死代码，注释与实际行为不符。实际行为=仅探测三个密钥文件（与 PRD F025 描述一致，但代码注释会误导重开发者以为有 agent 支持）。
- 建议：重构规格中明确「认证方式=密码 / 显式 key_path / 默认密钥探测」三种，agent 认证列为明确的非目标（或补充实现）。

### 5.3 PL-04【C】对 P4 FL-05/C-7 的风险定级校准

- P4 结论：加密失败明文落盘「与安全存储产品目标直接冲突」，列 C-7 用户决策。
- 本评审核实：触发条件近死（§1.3）；且降级写入的明文在下次 list 时必被解密链路吞掉（不可用数据）。风险真实存在但概率极低、后果自限。
- 校准建议：修复方向不变（拒绝保存，与 P4 V1 规格一致）、成本极低（删降级分支）；但其优先级应**让位于 DS-01（解密失败静默吞密码）**——后者是换机/改用户名的常态高频路径，且是用户可感知的数据丢失。两项应打包为同一个「凭据存储读写策略」决策项提交用户。
