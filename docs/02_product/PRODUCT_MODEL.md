## 1. 产品定位

**TermForge**（规划公开仓库名 `lys-term-forge`）是一个跨平台桌面运维工作台，面向开发者和运维人员，把 SSH 会话、SFTP 文件管理、端口转发、Runbook 批量执行和本地安全存储整合到一个桌面应用中。（来源：PRD §1）

**产品形态**：Tauri 2 桌面应用（Windows / macOS / Linux），单主窗口，VS Code 风格布局（活动栏 + 侧栏 + Tab 条 + 内容区 + 状态栏），窗口默认 1200×800（最小 800×500）。（来源：PRD §1、tauri.conf.json）

**一句话定位**：不是"又一个终端"，而是把常见运维动作收进一个桌面工作台。（来源：PRD §1）

**当前旧项目实现水位**（逆向结论，来源：REVERSE_ANALYSIS §① / PRD §1）：应用外壳、连接中心、真实 SSH 终端主链路（含主机密钥 TOFU 验证、多认证方式、PTY 同步、五态状态机）已实现；SFTP / 隧道 / Runbook / 设置为空状态占位；命令面板为占位实现。

## 2. 用户画像（来源：PRD §2，原始出处 产品需求.md §3）

| 画像 | 描述 | 核心诉求 |
|---|---|---|
| P1 高频 SSH 开发者 | 每天连接多台开发/测试机的后端/全栈工程师 | 快速连接、多 Tab 并行、连接配置复用、断线可见可重连 |
| P2 运维人员 | 管理批量服务器，执行巡检/发布脚本 | 连接中心 + Runbook 批量执行 + SFTP 传文件 + 执行历史 |
| P3 独立开发者/小团队 | 无企业级堡垒机预算 | 本地加密存储凭据、单机可用、无云依赖 |
| P4 记录型用户 | 希望统一管理连接和操作记录 | 连接档案、操作留痕（Runbook 执行历史） |

原始四类目标用户（产品需求.md §3）：① 需要频繁 SSH 的开发者；② 需要批量执行命令的运维人员；③ 独立开发者和小团队；④ 希望用桌面工具统一管理连接和操作记录的人。

## 4. 核心价值（来源：REVERSE_ANALYSIS §①「核心价值」）

1. 把"连上服务器干活"的完整动作（找连接 → 开终端 → 传文件 → 跑脚本）收进一个桌面工作台，而不是在多个工具间切换。
2. 连接配置本地加密持久化（AES-256-GCM，机器绑定密钥），避免明文密码落盘。
3. 多 Tab 并行会话 + 状态可视（idle/connecting/connected/closed/error 五态）。

**产品目标展开**（README.md「产品目标」）：不是"再造一个终端"，而是把连接中心、SSH 终端、SFTP 文件管理、端口转发、Runbook 批量执行、本地安全存储收进一个桌面工作台。

## 5. 商业/发布属性

- 定位为 lys 个人开源体系的一员（README.md：「Part of the lys personal open source system」），规划公开仓库名 `lys-term-forge`；当前仓库处于公开前打磨阶段（README.md「近期重点」：修终端链路 → 收口主流程 → 再推进 SFTP/转发/Runbook → 达到公开条件后进入 Gitee 主线）。
- 运行时无遥测/无更新检查/无云服务（REVERSE_ANALYSIS §⑧）——与"单机可用、无云依赖"的 P3 画像诉求一致。

## 6. 已知与定位相关的关键评审结论（重开发决策输入）

来源：`docs/product-review/PRODUCT_LOGIC_REVIEW.md`（总报告）：

1. 「三大块（SFTP/隧道/Runbook）是"工作台 vs SSH 客户端"定位分水岭」，做多少、先做哪块必须用户拍板（PL-01 三档建议）。
2. 8 项验收中"产品目标明确且可实现"为**部分达标**：目标-范围差距完全依赖规划功能弥合，取舍未决。
3. IA 层：骨架按终局设计（五视图工作台）搭建，内容兑现度 50%（10 页面中 4 个占位）——「承诺-兑现差」是 IA 层首要问题（INFORMATION_ARCHITECTURE_REVIEW.md IA-01）。

## 7. 产品原则（来源：产品需求.md §9，旧项目规划文档）

- 先做稳定工作流，不做花哨周边
- 当前代码现实优先于理想中的重构方案
- 终端、连接、文件、Runbook 是主链路
- 只有在值得时才做框架级重构
